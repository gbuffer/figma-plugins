# HTMLizer handoff

## What it is
A local Figma development plugin called HTMLizer. Grant pastes HTML (usually generated by Claude) into it, and it builds real Figma auto layout frames and text nodes from that HTML, so the result arrives as editable Figma layers rather than a flattened image or disconnected shapes.

## Repo
`gbuffer/figma-plugins`, with the plugin living in the `htmlizer/` folder (lowercase). Root of the repo has an index README listing the folders. The plugin's own README sits inside `htmlizer/` and starts with "# HTMLizer". It is the authoritative spec, with a version log, mapping rules, known limits and testing notes; read it before changing anything.

Local clone on Grant's Mac: `~/Development/figma-plugins`.

Manifest: `htmlizer/manifest.json`, with `name` set to `HTMLizer v5` and `id` set to `htmlizer`. The version lives in the `name` string (Figma rejects unknown manifest fields) and in the version line in `ui.html`; bump both on any change to converter behaviour and add a line to the README's version log.

## Versions
- **v1–v3** (on `main`): spacer handling in horizontal rows, FILL/HUG sizing deadlocks fixed with a measured FIXED parent and FILL children, `align-items: stretch` implemented.
- **v4** (on `svg-support`): `<svg>` elements passed whole to `figma.createNodeFromSvg` at their measured size, rather than dropped by the box-model walker.
- **v5** (on `svg-support`): rows whose filling children have different `flex-grow` values are pinned to measured FIXED widths, since Figma Fill cannot express a ratio.

## How it works
Renders the pasted HTML in a hidden iframe to get Chrome's real layout engine to do the work, walks the computed styles, and emits a JSON tree that the Figma sandbox code builds into frames.

Key technical decisions:
- Uses `layoutSizingHorizontal` / `layoutSizingVertical` rather than Figma's older sizing properties, applied after `appendChild` since FILL sizing cannot resolve without a parent already attached.
- Margins are converted to parent padding, child padding, transparent wrapper divs, or gap, since Figma has no native margin property.
- `margin-top: auto` is reproduced via a space-between layout with a content group, not a filling spacer, after a filling spacer caused circular height resolution and fixed heights everywhere.
- `<ul>` lists are converted to a single text node using `setRangeListOptions`, so bullets are native Figma bullet formatting on one text block rather than separate shapes per line.
- Full HTML documents (with `<!DOCTYPE>`, `<html>`, `<head>`, `<body>`) are parsed with `DOMParser` rather than `innerHTML`, because `innerHTML` discards structural tags and hoists meta elements, which the walker would otherwise mistake for the root. Stylesheets are carried across, `body` selectors are rewritten to target a stand-in div, and the walker picks the first visually rendered element as root rather than the first non-style child.

## The cardinal rule
The converter adapts to whatever HTML arrives. The HTML is never adapted to suit the plugin. This was established after Claude initially did the reverse, and is recorded as header comments in `ui.html` and `code.js`, plus the plugin's own README.

## Companion skill
A Claude skill, `html-diagram-for-figma`, governs how Claude writes HTML destined for this plugin: every non-leaf `<div>` gets a `data-name` attribute naming its role (not its look), lowercase and hyphenated, so the resulting Figma layer tree reads as a legible outline instead of a wall of identically named "div" layers.
